# optic

基于 **STM32F103RCT6** 的可见光数字通信工程，使用激光收发模块，通过 **OOK（亮灭键控）** 传输 ASCII 文字和数字语音。两块板烧录同一份固件，按键选择发送或接收。

**当前状态：已完成文字与语音功能，项目使用者于2026-10-23反馈实物调通完成。** 最新固件已编译通过，使用115200波特率传输。该完成情况来自使用者反馈，仓库尚未提供传输距离、误码率和长时间连续播放的量化记录。

## 最新更新（2026-10-23）

- 同步语音接收提示代码：VOICE+LISTEN下显示 `SIG:RX` / `SIG:WAIT`，与 `PLAY` 播放状态分别显示。
- 收到CRC校验通过的语音包后，`SIG:RX`保持约1秒；每个新包刷新保持时间，断流后自动回到 `SIG:WAIT`，切换模式或收发方向时清除提示。
- 保留文字发送的 `QUEUED #次数` 可见提示、最新激光直连接线图及下方完整使用步骤。

## 功能

- 文字模式：按键发送预设的 `HELLO`，接收后在 OLED 上显示；接口支持每帧 1～32 字节 ASCII 数据。
- 语音模式：8kHz、8位、单声道无符号 PCM，ADC 采样后通过光链路传输，接收端 DAC 恢复音频。
- 半双工：支持切换 SEND / LISTEN，同一时刻选择一个收发方向。
- 发送提示：文字成功入队后显示 `QUEUED #次数` 约1秒，之后保留累计次数。
- 语音接收提示：最近1秒内收到有效语音包时显示 `SIG:RX`，否则显示 `SIG:WAIT`。
- CRC16 校验、语音序号统计、接收缓冲、断流静音及错误计数。
- 定时器和 DMA 完成采样、搬运与播放；按键采用非阻塞扫描。

当前 K3 发送的是程序内预设字符串，没有实现电脑串口输入任意文字，也没有实现确认应答、自动重传、压缩编码或双向同时通话。

## 工作流程

```text
文字 ──────────────────────┐
                           ├→ 封包 / CRC → USART2 TX / PA2 → 激光模块 S
音频 → 调理 → PA1 ADC → PCM ┘                                  │
                                                              光
接收模块 OUT → PA3 → 定时器 / DMA采样 → 软件反相 → 8N1解码 → 帧校验
                                                          ├→ OLED显示文字
                                                          └→ 缓冲 → PA4 DAC → 功放 → 喇叭
```

发射端使用硬件 USART2；接收端 PA3 是普通 GPIO，由 TIM5 + DMA 采样后软件恢复串口数据。接收模块有光输出低电平，软件在逐位解码前执行反相。

语音先转换为数字样本，再通过激光亮灭传输；激光亮度不直接跟随模拟声音幅度。

## 硬件

| 器件 | 用途 |
|---|---|
| STM32F103RCT6 开发板 ×2 | 收发两端，主频配置为72MHz |
| 激光发射模块、激光接收模块 | 与下方厂家资料对应，3.3V供电，高电平发射、有光低电平接收 |
| 3.3V兼容 I²C OLED ×2 | 显示状态与文字 |
| 每板4个外接常开按键 | 选择模式、方向及启停 |
| 手机音源 | 输入音频 |
| LM386功放板、喇叭 | 按音频图连接；图中采用发射侧和接收侧各一块功放 |
| 电阻、10kΩ衰减电位器、耦合及滤波电容 | 音频衰减、偏置和滤波 |

若只有一块 LM386，可放在接收侧，手机音频直接经过输入调理后送 PA1。PA1 不得直接连接手机或功放的未调理输出。

## 接线

### 激光链路：当前使用直接连接版本

按配套厂家资料的“方法2”连接发射模块，**不使用原来普通 LED 的外部 S8050 驱动支路**。按模块丝印认引脚，不凭照片左右顺序接线。

| 所在端 | 模块引脚 | STM32引脚 |
|---|---|---|
| 发射端 | ＋ / VCC | 3V3 |
| 发射端 | － / GND | GND |
| 发射端 | S | **PA2 / A2，直接连接** |
| 接收端 | VCC | 3V3 |
| 接收端 | GND | GND |
| 接收端 | OUT | **PA3 / A3，直接连接** |

- PA2高 → 激光亮 → 接收OUT低；PA2低 → 激光灭 → 接收OUT高。
- 默认 `OOK_RX_INVERTED=1`，接收端不加外部反相器。
- SEND时串口空闲高电平，因此激光常亮；发送文字时快速亮灭，肉眼通常看不出闪烁。
- LISTEN时本机PA2拉低，发射器熄灭。
- 每块板与本侧外围共地；两板通过光通信，不必互接地线或串口线。
- 避免激光直射眼睛。

![当前激光直连接线总览](接线图/激光直连版-接线总览.png)

### OLED与按键：两块板相同

| 外设 | STM32引脚 |
|---|---|
| OLED VCC / GND | 3V3 / GND |
| OLED SCL / SDA | PB8 / PB9 |
| K1 | PB1，另一端接GND |
| K2 | PB0，另一端接GND |
| K3 | PA5，另一端接GND |
| K4 | **PC0**，另一端接GND |

按键使用按下才导通的两脚。板上的 RST、BOOT0 不作为功能按键。

PB13始终为低电平，未接路径选择电路时可悬空不接。PC13为可选的低有效文字接收指示，不能据此认定任意开发板的板载LED都接在PC13。

### 音频接口

| 引脚 | 功能 | 要求 |
|---|---|---|
| PA1 / A1 | ADC音频输入 | 衰减、隔直、约1.65V偏置及低通；输入全程保持0～3.3V |
| PA4 / A4 | DAC音频输出 | 经过滤波和隔直接功放音频输入，不能直接带喇叭 |

手机插入发送侧 LM386 的3.5mm输入。其喇叭输出经过图中的额外10kΩ衰减电位器、耦合电容及偏置电路后，才进入PA1。先确认喇叭负端与电源负端导通，再按图共地。功放使用图示5V供电。

![音频与模块接口详图](接线图/激光直连版-音频接线.png)

- 图中的1µF耦合电容已用 **4.7µF有极性电容**替代。
- 输入电容：当音源侧直流约0V时，正极朝PA1偏置侧；否则正极朝直流电位较高的一侧。
- 输出电容：当功放输入侧直流约0V时，正极朝PA4侧。
- 22nF / 47nF缺件可先留空进行初调，但会减弱滤波；不能用导线或4.7µF替代这些对地滤波支路，正式语音调试应补齐合适滤波。
- PA1接入前测量偏置和音频幅度：静音约1.65V，初调可约1Vpp，不能触及或超过0～3.3V范围。

详细说明见 [激光模块接线与联调](接线图/激光模块-方案二接线说明.md)。文件夹中保留的普通LED、旧“最终版”和非直连图片属于历史方案，以本README引用的两张直连图为准。

## 按键操作

上电默认 **TEXT + LISTEN**。按键松开时触发，不需要一直按住。

| 按键 | 功能 |
|---|---|
| K1 | 切换TEXT / VOICE，停止旧模式的音频和发送队列 |
| K2 | 切换SEND / LISTEN，停止正在进行的语音 |
| K3 | TEXT+SEND发一次HELLO；VOICE+SEND开始采样，再按一次停止 |
| K4 | 停止语音、回到TEXT、清除接收文字，保留当前收发方向 |

### 先传文字

1. 两块板烧录同一工程，先只连接光链路、OLED与按键。
2. 接收板保持 **TEXT + LISTEN**，对准光路；接收端不需要按K3。
3. 发射板按K2切到 **TEXT + SEND**。
4. 发射板按下并松开K3，提交一次 `HELLO`。
5. 接收板 `RX:` 后出现 `HELLO` 表示接收成功，文字会保留显示。

若发送时接收端尚未准备好，准备好后再按发送端K3即可，不必一直发送。

### 再传语音

1. 确认文字链路稳定，再完成音频调理、功放与喇叭接线。
2. 接收板按K1选择 **VOICE**，保持 **LISTEN**。
3. 发射板按K1选择 **VOICE**，保持 **SEND**，按K3开始。
4. 手机播放人声，观察发送端 `IN:ON`、`LV`；接收端收到有效语音包后显示 `SIG:RX`，`RX`递增，缓冲后显示 `PLAY:ON`并输出声音。
5. 发射端再按K3停止；接收端约100ms没有有效语音包后停止播放。K4可停止并返回文字模式。

## OLED提示

第一行 `OOK SWRX 115200 INV` 表示当前软件反相接收、115200波特率配置。

| 提示 | 含义 |
|---|---|
| `TX: LISTEN #0` | 当前为接收方向 |
| `TX: READY #次数` | 本机发送队列及串口空闲，保留累计文字提交次数 |
| `TX: BUSY #次数` | 队列或串口仍在发送 |
| `TX: QUEUED #次数` | 文字请求成功入队后保留约1秒；**不是对端接收确认** |
| `TX: REJECT #次数` | 发送方向下文字请求未能入队，不增加次数 |
| `FE` / `OV` | 接收软件8N1起始/停止位错误 / 接收采样缓冲覆盖次数 |
| `IN:ON` / `IN:ERR` | 正在采集 / ADC初始化校准失败 |
| `PLAY:ON` | 已开始播放 |
| `SIG:RX` / `SIG:WAIT` | VOICE+LISTEN下最近1秒内收到CRC正确的语音包 / 等待有效语音包；连续接收时保持RX |
| `LV` | 最近64点ADC峰峰值，12位ADC码值，非电压读数 |
| 语音页 `RX` / `CRC` / `GAP` | 有效语音包数 / CRC错误数 / 可识别的序号缺口数 |

文字次数为本机成功入队次数，上电复位清零，K4不清零。FE、OV不是发送次数，发送端始终为0并不能用于判断是否发送成功；接收端为0也不能证明已收到数据，应查看 `RX: HELLO`。

语音 `RX` 是有效语音包累计数，正常连续发送时理想约每秒增加125；断流后保留数值，上电或复位清零，模式切换和K4不清零。`SIG:RX`说明最近收到过有效包，`PLAY:ON`说明DAC播放流程已启动，两者不直接检测喇叭是否实际出声。

## 编译与烧录

当前工程使用 **Keil µVision 5 + ARM Compiler 5**，目标名称为 `LED Optical Communication`。

1. 安装ARMCC 5（已使用版本 `V5.06 update 5 build 528`）及 `Keil.STM32F1xx_DFP`（工程记录为2.4.0）。不要直接切到ARM Compiler 6而不做兼容调整。
2. 将仓库放入本地文件夹，打开根目录 **`Project.uvprojx`**。
3. 确认器件为 `STM32F103RC`，使用高密度启动文件 `startup_stm32f10x_hd.s`，宏为 `USE_STDPERIPH_DRIVER, STM32F10X_HD`。
4. 执行 **Rebuild**。默认输出为 `Objects/Project.axf`，没有启用HEX生成；若需要HEX，可在Target的Output页勾选Create HEX File。
5. Keil个人调试配置没有纳入版本控制。首次打开需选择实际使用的ST-Link等下载器，连接SWDIO、SWCLK、GND及所需参考电源，检查Flash下载算法后再下载。
6. 将同一固件分别烧录到两块板，复位后通过K2区分收发方向。

工程使用标准外设库，所需CMSIS、启动文件和SPL源码已包含在仓库内。系统配置按8MHz外部晶振、72MHz系统时钟使用，换板时需核对实际晶振；音频定时器参数依赖该时钟配置。

最近一次编译（语音接收提示版本）：**0 errors / 0 warnings**，Code=17780、RO-data=3308、RW-data=100、ZI-data=8252字节。对应Flash内容约20.7KiB，RAM静态分配与栈/堆预留约8.2KiB。该记录是本地已有编译结果，不代表完成硬件测试。编译产物与日志由 `.gitignore` 排除，克隆后自行编译生成。

## 参数与协议

参数位于 `Hardware/OOK.h` 和 `Hardware/Voice.h`：

| 参数 | 当前值 |
|---|---|
| `OOK_BAUD_RATE` | 115200，8N1，LSB先发 |
| `OOK_RX_INVERTED` | 1，有光输入低 |
| `OOK_MAX_PAYLOAD` | 32字节文字 |
| `VOICE_SAMPLE_RATE` | 8000Hz |
| `OOK_AUDIO_SAMPLES` | 64点 / 包，即8ms音频 |

帧格式：

```text
A5 5A | TYPE | SEQ | LEN | PAYLOAD | CRC_LO | CRC_HI
```

- TYPE=1为文字，LEN=1～32；TYPE=2为语音，LEN=64。
- CRC16-CCITT-FALSE：初值0xFFFF，多项式0x1021，不反射、无末异或，覆盖TYPE至PAYLOAD，低字节先发送。
- 8位序号循环递增；CRC错误丢包，没有应答或重传。
- 每个语音包71字节，含8N1开销共710bit，每秒125包，共88750bit/s。
- 修改文字内容：编辑 `User/main.c` 的 `hello` 字符串，限制在32字节ASCII内。
- 如需降低波特率调试文字，必须两端同步修改并烧录；降低到无法承载语音数据率时不能继续使用当前实时语音配置，代码没有自动降速保护。

## 代码结构

```text
Project.uvprojx             Keil工程
User/main.c                初始化、按键事件、模式、OLED和文字发送提示
Hardware/OOK.c / .h        TX队列、DMA发送、软件接收、帧解析与CRC
Hardware/Voice.c / .h      ADC采样、PCM、环形缓冲与DAC播放
Hardware/Key.c / .h        非阻塞按键扫描
Hardware/OLED*             OLED显示与字库
Hardware/LED.c / .h        可选PC13文字接收指示
System/                    延时函数
Start/                     Cortex-M3、系统时钟与高密度启动文件
Library/                   STM32F10x标准外设库
接线图/                    当前接线图、SVG源文件及历史方案资料
```

| 资源 | 分工 |
|---|---|
| TIM2 | 1ms时间服务，内部每20ms扫描按键 |
| TIM3 + ADC1 + DMA1通道1 | 8kHz采样PA1，128点循环缓冲，半区64点 |
| USART2 + DMA1通道7 | PA2非阻塞发送，4槽队列最多存3包 |
| TIM5 + DMA2通道2 | PA3约4倍位速率采样，1024点循环区与512点静态快照 |
| TIM6 + DAC1 + DMA2通道3 | PA4以8kHz播放，128点循环缓冲 |
| 512字节语音环形区 | 预存3包后播放，缺样本填静音、缓冲满时丢包 |

OLED约每100ms刷新。音频及光链路的定时采样由硬件触发，DMA中断负责分块处理；这不等于所有主循环操作都是非阻塞的，OLED仍为同步刷新。

## 调试与限制

- **激光常亮**：TEXT+SEND空闲常亮是正常现象，不能靠肉眼是否闪烁判断通信。
- **没有HELLO**：先检查发送板为SEND、接收板为LISTEN，再查引脚、光路；接收模块OUT持续有光应低、遮挡后应高，且输入电平不超过3.3V。
- **FE增加**：检查极性、信号波形、模块响应速度与两端波特率；**OV增加**表示采样缓冲未及时处理。
- **有文字但语音断续**：检查CRC/GAP、音频电平、滤波和供电；8kHz/8位PCM适用于人声演示，不是高保真音乐配置。
- **RX递增、SIG:RX、PLAY:ON正常但喇叭无声**：先断电、断开PA4输入连接，用手机直接接接收侧功放，确认功放供电、音频线和喇叭正常；再恢复PA4→滤波/隔直→功放输入的连接。手机直接接功放仍无声时，先调通这段独立播放链路；同时查看发送端LV是否随声音变化，排除一直在传静音。
- 两端独立晶振会产生长期采样率偏差。当前没有自适应重采样，长时间播放可能出现缓冲不足或溢出。
- 配套模块没有给出最高响应速率。现有实物调通反馈不等于所有同类模块、距离和环境都能达到相同效果；更换硬件后仍需核对电平、输入幅度和光链路带宽。当前没有光链路误码率、长时间连续音频或处理时限的量化报告。
